Day01

第一天的内容是围绕 Bean 的，对于 bean，主要是写了两个简单的模块，很多的时间其实都是用于踩一些杂七杂八的坑上了。

先说一下最核心的 BeanDefinition 和 BeanFactory。前者是定义一个 bean 的，最开始我们用 Object 这个简单的类型去描述，后续会更新。后者目前是注册和查找并返回一个 bean 的，bean 的存储结构，因为要通过一个名字去找到一个 bean，很容易想到使用哈希。为了应对并发，我们这里用的是 ConcurrentHashMap。

BeanFactory 主要的功能是提供注册 bean 和获取 bean 的功能，也由存放全局的 bean 容器的作用。

过程中有两个问题：

  • 这里的 map 应该存 BeanDefinition 还是 Object？
    • 因为在获取 bean‘的时候不一定仅仅是获取 bean 本身，bean 定义相关的字段或者方法也需要使用，所以不能写死了。
  • map 使用的是 ConcurrentHashMap，为什么呢？存在并发吗？
    • ConcurrentHashMap 是一个高效的应对并发的数据结构，由于 bean 是单例模式，BeanMap 是全局共享的。所以会有并发写的情况，因此要使用这个数据结构。

Java 项目结构

之前我并不知道 classpath, 这个的主要作用是让 JVM 知道去哪里加载包，比如说我测试的时候需要用到 juit，那么我就需要将 junit 的 jar 包加到 classpath 下，比较繁琐。所以我在 ai 的建议下使用了 maven 构建

一个普通的 maven 项目结构应该如下：

一个项目下面有一个 src 和 target, 前者用于存放代码，后者用于存放编译后的字节码文件。java 子目录放的是业务代码，resources 用于存放配置文件。

而 pom.xml 最主要的用途是依赖管理，在里面声明依赖之后 maven 会自动下载 jar 包（某个 package 下所有的 class 文件）并在编译/测试的时候加入 classpath。

然后在项目目录下使用一个简单的 maven 命令就可以成功构建，非常的方便。
